AdminServer Documentation

A complete, plain guide to every part of the panel — for the administrator who runs the server, and for the account owner who runs one site on it.

What AdminServer is

AdminServer is a hosting control panel for AlmaLinux, Rocky and RHEL (9 & 10). It turns one server into a place where several websites live side by side, each isolated from the others, and gives you a browser page to manage all of it — no SSH required for everyday work.

Two kinds of user

  • Administrator — runs the whole server: creates accounts, installs PHP and Node.js versions, hardens security, manages DNS and mail, takes backups, and watches the system.
  • Account owner — manages their own account only: their websites, files, databases, mailboxes and backups. They never see other accounts or the server's internals.

How the screen is laid out

  • Top bar — language toggle, light/dark mode, notifications, server-health badge, and the server's host name.
  • Side menu (left) — the sections you are allowed to open, grouped by purpose. For an open account it also lists its sites, and under each site its pages and sub-domains.
  • Breadcrumb (top of the page) — shows where you are and lets you step back up.
Every address is a real link. Reloading the page, or sharing a link, lands on exactly the same place.

Signing in & the top bar

After install, the panel prints a one-time password and a URL like https://SERVER_IP:8443. Open it, sign in, and change the initial password when asked — the panel refuses to do anything else until you do.

If you ever forget it, run on the server: sudo adminserver reset-password.

The top bar, left to right

  • Language — switch the whole panel between English and Arabic at any time.
  • Light / dark mode — the moon/sun button; your choice is remembered.
  • Notifications — the bell, with a red count of unread items.
  • Server health — a percentage badge (admin only); click it for the Security Center.
  • Host name — the server this panel runs on.

Home — server dashboard Admin

The administrator's home page is the server at a glance: an overall health percentage, CPU / memory / disk use, how many accounts and sites are hosted, and a short list of anything that needs attention. An account owner's home is their own account instead, with their sites and disk usage.

Security Center Admin

The heart of the panel. It runs more than 28 checks on how the server is hardened — the firewall, SELinux, SSH, kernel settings, service isolation, and more. Each check is one row:

  • A green / red dot tells you if it passes.
  • An explanation in plain words: what it is and why it matters.
  • A Fix button that applies the correct setting in one click.
  • A safe rollback — if a fix ever causes trouble, you can undo it.
Aim for 100%. A freshly installed server reaches it by opening this page and fixing each item — the result is the same hardened server every time.

SSH Keys Admin

Manage the public keys that may log into the server over SSH as root. Add your key here so password SSH can be turned off (the Security Center recommends it), leaving key-only access.

Accounts Admin

An account is one customer or project. Each account is a real Linux user with its own home, its own process slice, its own disk quota — fully walled off from the others.

List Accounts

Every account with its site count and disk use. Open one to see its websites, reset its password, or delete it.

Create Account

Pick a name (lowercase letters and digits). The panel creates the Linux user, its home, its slice and quota, and gives you a one-time password to hand over.

Resources & limits

Each account has a Resources page showing live CPU, memory and disk use. The administrator can cap an account here (CPU share, memory, number of processes, disk quota) so one account can never starve the rest. Owners see their usage but not the limits card.

PHP Versions Admin

Install several PHP versions side by side (e.g. 8.1, 8.2, 8.3). They are installed once, centrally and read-only; each site then picks the one it runs on. This page shows each version, how many sites use it, which are past end-of-life, and lets you install or remove one and manage its extensions.

A version in use by any site or sub-domain cannot be removed until nothing uses it.

Node.js Versions Admin

Exactly like PHP, but for Node.js. Install the majors you want to offer (e.g. 20, 22, 24); the panel downloads the official release, checks its checksum, and stores it read-only. A site or sub-domain that runs as a Node app then chooses one of these.

DNS Admin

If you want the server to answer DNS for its domains, set the server's name servers here (ns1…, ns2…). Once set, each site gets a DNS tab where its zone and records are managed on this server directly.

Mail Admin

Turn on mail hosting for the server (Postfix + Dovecot, with anti-spoofing). This sets the mail host name once; afterwards each site can enable mail and create mailboxes from its own Mail tab.

Monitoring Admin

Every active session: who is signed in, from which address and country. You can sign a suspicious session out. All of it is kept locally — no external service ever sees it.

Activity Log Admin

A record of every sign-in and every command the panel ran — with the user, address and time. Use it to see exactly what happened and when.

Network Admin

The server's network traffic over time, so you can see spikes and which hosts are busiest.

Settings Admin

Panel-wide preferences: for example, lock each session to the address it was created at (so a stolen cookie is useless elsewhere), and other safety options. Account owners have their own smaller settings (password, notifications).

Billing & Plans Admin

The business side, when you use it: the plans you offer, who owes what (orders & invoices), and requests to join. An owner sees only their own plan and invoices under Billing.

Sites & their tabs

A site is one domain (e.g. example.com). Add one from inside an account; its files live in the account's home. Open a site and it unfolds in the side menu into a set of tabs. The tabs shown depend on the site's type: a PHP site shows the PHP tab, a Node site shows the Node tab.

Overview

The site at a glance: SSL certificate status, whether DNS points to this server, the site type, and the number of databases. Here you also:

  • Choose the site type — PHP or Node.js. Picking PHP stops any Node app; picking Node hands every request to your Node process.
  • Choose the web server for a PHP site — nginx alone, or Apache behind it (for .htaccess).
  • See and fix any issues (missing certificate, DNS not pointing here) in one click.
  • Remove the site (its files stay in the account's home).

File Manager

A full file manager for the site's folder: browse, upload by drag-and-drop, create, rename, move, delete, and extract archives. A built-in code editor (Monaco) opens text files for editing. Everything runs as the account's own user, so permissions stay correct.

Sub-domains

Host names under the site (e.g. blog.example.com), each served from a folder inside the site and each with its own certificate. Create one with just a name; it gets a folder automatically. Each row shows its type and has an Overview button that opens the sub-domain as its own small site (see below), and a Remove button.

PHP Configuration

For a PHP site. Three parts:

  • Version — pick which installed PHP version this site runs on; the change is immediate.
  • Extensions — turn on the extensions this site needs, from those the administrator installed.
  • Options — adjust the safe php.ini settings (upload size, memory, time limits…).

Node.js

For a Node site. Enable the app, choose its Node version, the start command (e.g. npm start), the app folder, and any environment variables. The app runs as a long-lived service in the account's slice; nginx forwards every request to it over a private socket (WebSockets included). The page shows whether it is running, its recent logs, and buttons to start / stop / restart it and to run npm install.

Databases

Create a MariaDB database for the site, each with its own user. The panel shows the connection details and a one-time password, resets a password, opens phpMyAdmin for one database, or deletes a database. Delete a database before removing its site so its data is never lost by accident.

DNS

If the server runs DNS, this tab manages the site's zone and records (A, AAAA, CNAME, MX, TXT, …). If DNS is managed elsewhere, the panel still shows exactly which records to add there.

Mail

Enable mail for the domain, create and delete mailboxes, change their passwords, and read the exact DNS records (SPF, DKIM, MX…) the mail needs — with one click to publish them if the zone is on this server. Connection details for any mail client are shown, and webmail if it is set up.

Traffic

The site's visitors and requests over time (hour, day, week…), with a breakdown by host. Each account has a wider traffic view too.

Terminal

A web terminal that runs as the account's own user, inside an isolated session — handy for composer, git, or quick commands without full SSH access. It can never reach another account or the system.

A sub-domain as its own site

Each sub-domain is a small site in its own right. It appears in the side menu under its parent, and opening it (or its Overview button) gives it its own pages:

  • Overview — its type, SSL, DNS, folder, issues and removal.
  • Files — jumps to its own folder in the file manager.
  • PHP or Node — its own PHP version, or its own Node app, independent of the parent site.

It keeps all of this while living inside the parent account's user and slice, so it never crosses the account's isolation.

Backups Everyone

Take a backup of an account, and send it off the server so a lost server is never a lost backup. Add a destination — MEGA or any S3-compatible storage (Backblaze B2, Wasabi, Cloudflare R2) — test it, then create backups and restore from them in a click.

Updating the panel Admin

The panel checks an official channel for new versions. When one is available, a banner offers to update. The update is verified twice — its checksum and a cryptographic signature — and refused if either fails, so only a genuine build from the real publisher is ever installed. The panel installs it and restarts itself; your sites keep running.

How your data is kept safe

  • Privilege separation — a small privileged helper does the real work; the web face has no powers of its own and only asks for named operations.
  • Per-account isolation — a Linux user and slice per account, with CPU, memory, process and disk limits, enforced by SELinux. An attacker inside one site never reaches another.
  • Verified updates — every update is checksum- and signature-checked before it is installed.
  • Local records — sign-ins and commands are logged on the server itself; no external service is involved.
Questions or a problem? Open the Security Center first — it explains and fixes most things on its own.

ما هي AdminServer

AdminServer لوحة تحكّم استضافة لأنظمة AlmaLinux وRocky وRHEL (9 و10). تحوّل سيرفرًا واحدًا إلى مكان تعيش فيه عدّة مواقع جنبًا إلى جنب، كلٌّ معزول عن الآخر، وتمنحك صفحة في المتصفح لإدارة كل شيء — دون الحاجة إلى SSH للعمل اليومي.

نوعان من المستخدمين

  • المدير — يدير السيرفر كاملًا: ينشئ الحسابات، يثبّت إصدارات PHP وNode.js، يرفع مستوى الحماية، يدير DNS والبريد، يأخذ النسخ الاحتياطية، ويراقب النظام.
  • مالك الحساب — يدير حسابه فقط: مواقعه وملفاته وقواعد بياناته وصناديق بريده ونسخه الاحتياطية. لا يرى الحسابات الأخرى ولا داخل السيرفر.

كيف تُرتَّب الشاشة

  • الشريط العلوي — تبديل اللغة، الوضع الفاتح/الداكن، الإشعارات، شارة صحّة السيرفر، واسم مضيف السيرفر.
  • القائمة الجانبية — الأقسام المسموح لك بفتحها، مُجمّعة حسب الغرض. وعند فتح حساب تُدرِج مواقعه، وتحت كل موقع صفحاته ونطاقاته الفرعية.
  • مسار التنقّل (أعلى الصفحة) — يبيّن أين أنت ويتيح الرجوع للأعلى.
كل عنوان رابط حقيقي. تحديث الصفحة أو مشاركة الرابط يعيدك إلى المكان نفسه بالضبط.

تسجيل الدخول والشريط العلوي

بعد التثبيت تطبع اللوحة كلمة مرور لمرة واحدة ورابطًا مثل https://SERVER_IP:8443. افتحه، سجّل الدخول، وغيّر كلمة المرور الأولية عند الطلب — فاللوحة ترفض أي شيء آخر حتى تفعل ذلك.

وإن نسيتها، شغّل على السيرفر: sudo adminserver reset-password.

الشريط العلوي

  • اللغة — بدّل اللوحة كاملة بين الإنجليزية والعربية في أي وقت.
  • الوضع الفاتح/الداكن — زرّ القمر/الشمس؛ ويُحفظ اختيارك.
  • الإشعارات — الجرس، مع عدّاد أحمر للعناصر غير المقروءة.
  • صحّة السيرفر — شارة نسبة مئوية (للمدير فقط)؛ اضغطها لفتح مركز الحماية.
  • اسم المضيف — السيرفر الذي تعمل عليه هذه اللوحة.

الرئيسية — لوحة السيرفر مدير

صفحة المدير الرئيسية تُظهر السيرفر بلمحة: نسبة صحّة عامة، واستخدام المعالج والذاكرة والقرص، وعدد الحسابات والمواقع المستضافة، وقائمة قصيرة بما يحتاج انتباهًا. أما مالك الحساب فرئيسيّته هي حسابه نفسه، بمواقعه واستهلاك قرصه.

مركز الحماية مدير

قلب اللوحة. يُجري أكثر من 28 فحصًا على تصلّب السيرفر — الجدار الناري، SELinux، SSH، إعدادات النواة، عزل الخدمات، وغيرها. كل فحص سطر واحد:

  • نقطة خضراء/حمراء تخبرك هل نجح.
  • شرح بكلمات واضحة: ما هو ولماذا يهمّ.
  • زرّ إصلاح يطبّق الإعداد الصحيح بنقرة واحدة.
  • تراجع آمن — إن سبّب إصلاحٌ مشكلةً يمكنك التراجع عنه.
استهدف ١٠٠٪. السيرفر المثبّت حديثًا يبلغها بفتح هذه الصفحة وإصلاح كل بند — والنتيجة سيرفر مُحصَّن بنفس القدر في كل مرة.

مفاتيح SSH مدير

أدِر المفاتيح العامة المسموح لها بالدخول إلى السيرفر عبر SSH كـ root. أضف مفتاحك هنا لتتمكّن من إيقاف دخول SSH بكلمة المرور (كما يوصي مركز الحماية)، فيبقى الدخول بالمفتاح فقط.

الحسابات مدير

الحساب عميل أو مشروع واحد. كل حساب مستخدم لينكس حقيقي له مجلده الخاص، وشريحة عمليات خاصة، وحصّة قرص خاصة — معزول تمامًا عن الآخرين.

قائمة الحسابات

كل حساب مع عدد مواقعه واستهلاك قرصه. افتح حسابًا لترى مواقعه، أو تعيد ضبط كلمة مروره، أو تحذفه.

إنشاء حساب

اختر اسمًا (أحرف إنجليزية صغيرة وأرقام). تنشئ اللوحة مستخدم لينكس ومجلده وشريحته وحصّته، وتعطيك كلمة مرور لمرة واحدة لتسلّمها.

الموارد والحدود

لكل حساب صفحة الموارد تُظهر استخدام المعالج والذاكرة والقرص لحظيًا. ويستطيع المدير تحديد سقف للحساب هنا (حصّة المعالج، الذاكرة، عدد العمليات، حصّة القرص) كي لا يستنزف حسابٌ واحد البقية. يرى الملّاك استهلاكهم لكن لا تظهر لهم بطاقة الحدود.

إصدارات PHP مدير

ثبّت عدّة إصدارات PHP جنبًا إلى جنب (مثل 8.1 و8.2 و8.3). تُثبَّت مرة واحدة مركزيًا للقراءة فقط؛ ثم يختار كل موقع الإصدار الذي يعمل عليه. تُظهر هذه الصفحة كل إصدار، وكم موقعًا يستخدمه، وأيّها انتهى دعمه، وتتيح التثبيت أو الإزالة وإدارة الإضافات.

لا يمكن إزالة إصدار يستخدمه أي موقع أو نطاق فرعي حتى يتوقف استخدامه تمامًا.

إصدارات Node.js مدير

تمامًا كـ PHP لكن لـ Node.js. ثبّت الإصدارات الرئيسية التي تريد إتاحتها (مثل 20 و22 و24)؛ تنزّل اللوحة الإصدار الرسمي وتتحقّق من بصمته وتخزّنه للقراءة فقط. ثم يختار منها الموقعُ أو النطاقُ الفرعي الذي يعمل كتطبيق Node.

DNS مدير

إن أردت أن يجيب السيرفر عن DNS لنطاقاته، اضبط خوادم الأسماء هنا (ns1… وns2…). وبعد ضبطها يحصل كل موقع على تبويب DNS تُدار منه منطقته وسجلّاته على هذا السيرفر مباشرة.

البريد مدير

فعّل استضافة البريد للسيرفر (Postfix وDovecot، مع مكافحة الانتحال). يضبط هذا اسم مضيف البريد مرة واحدة؛ وبعدها يستطيع كل موقع تفعيل البريد وإنشاء صناديقه من تبويب البريد الخاص به.

المراقبة مدير

كل جلسة نشطة: من سجّل الدخول، ومن أي عنوان وبلد. ويمكنك إخراج جلسة مشبوهة. وكل ذلك محفوظ محليًا — لا تراه أي خدمة خارجية أبدًا.

سجل العمليات مدير

سجلٌّ لكل دخول ولكل أمر نفّذته اللوحة — مع المستخدم والعنوان والوقت. استخدمه لترى بالضبط ماذا حدث ومتى.

الشبكة مدير

حركة شبكة السيرفر عبر الزمن، لترى الارتفاعات وأكثر المضيفين انشغالًا.

الإعدادات مدير

تفضيلات على مستوى اللوحة: مثلًا ربط كل جلسة بالعنوان الذي أُنشئت منه (فتصبح الكوكي المسروقة بلا فائدة في مكان آخر)، وخيارات أمان أخرى. ولمالكي الحسابات إعداداتهم الأصغر (كلمة المرور، الإشعارات).

الفوترة والخطط مدير

الجانب التجاري عند استخدامه: الخطط التي تقدّمها، ومن عليه ماذا (الطلبات والفواتير)، وطلبات الانضمام. ويرى المالك خطّته وفواتيره فقط تحت الفوترة.

المواقع وتبويباتها

الموقع نطاق واحد (مثل example.com). أضفه من داخل حساب؛ وتعيش ملفاته في مجلد الحساب. وعند فتح موقع يتوسّع في القائمة الجانبية إلى مجموعة تبويبات. والتبويبات المعروضة تعتمد على نوع الموقع: موقع PHP يُظهر تبويب PHP، وموقع Node يُظهر تبويب Node.

نظرة عامة

الموقع بلمحة: حالة شهادة SSL، وهل يشير DNS إلى هذا السيرفر، ونوع الموقع، وعدد قواعد البيانات. ومن هنا أيضًا:

  • اختر نوع الموقع — PHP أو Node.js. اختيار PHP يوقف أي تطبيق Node؛ واختيار Node يسلّم كل الطلبات إلى عملية Node الخاصة بك.
  • اختر خادم الويب لموقع PHP — nginx وحده، أو Apache خلفه (من أجل .htaccess).
  • راجع وأصلح أي مشاكل (شهادة ناقصة، DNS لا يشير هنا) بنقرة واحدة.
  • أزِل الموقع (تبقى ملفاته في مجلد الحساب).

مدير الملفات

مدير ملفات كامل لمجلد الموقع: تصفّح، ورفع بالسحب والإفلات، وإنشاء وإعادة تسمية ونقل وحذف، وفكّ الأرشيفات. ومحرّر أكواد مدمج (Monaco) يفتح الملفات النصية للتعديل. وكل شيء يعمل بهوية مستخدم الحساب نفسه، فتبقى الصلاحيات صحيحة.

النطاقات الفرعية

أسماء مضيفين تحت الموقع (مثل blog.example.com)، كلٌّ يُخدَم من مجلد داخل الموقع وله شهادته الخاصة. أنشئ واحدًا بالاسم فقط؛ فيحصل على مجلد تلقائيًا. ويُظهر كل صف نوعه وفيه زرّ نظرة عامة يفتح النطاق الفرعي كموقع مصغّر مستقل (انظر أدناه)، وزرّ إزالة.

تكوين PHP

لموقع PHP. ثلاثة أجزاء:

  • الإصدار — اختر إصدار PHP المثبّت الذي يعمل عليه الموقع؛ ويُطبَّق التغيير فورًا.
  • الإضافات — فعّل الإضافات التي يحتاجها الموقع، من بين ما ثبّته المدير.
  • الخيارات — عدّل إعدادات php.ini الآمنة (حجم الرفع، الذاكرة، حدود الوقت…).

Node.js

لموقع Node. فعّل التطبيق، واختر إصدار Node، وأمر التشغيل (مثل npm start)، ومجلد التطبيق، وأي متغيّرات بيئة. يعمل التطبيق كخدمة دائمة داخل شريحة الحساب؛ ويمرّر nginx كل طلب إليه عبر مقبس خاص (بما في ذلك WebSocket). وتُظهر الصفحة هل هو يعمل، وسجلّه الأخير، وأزرار التشغيل/الإيقاف/إعادة التشغيل وتشغيل npm install.

قواعد البيانات

أنشئ قاعدة بيانات MariaDB للموقع، كلٌّ بمستخدمها الخاص. تُظهر اللوحة بيانات الاتصال وكلمة مرور لمرة واحدة، وتعيد ضبط كلمة مرور، وتفتح phpMyAdmin لقاعدة واحدة، أو تحذف قاعدة. احذف قاعدة البيانات قبل إزالة موقعها كي لا تُفقَد بياناتها دون قصد.

DNS

إن كان السيرفر يدير DNS، يدير هذا التبويب منطقة الموقع وسجلّاته (A وAAAA وCNAME وMX وTXT…). وإن كان DNS مُدارًا في مكان آخر، تُظهر اللوحة بالضبط أي سجلّات تُضاف هناك.

البريد

فعّل البريد للنطاق، وأنشئ واحذف الصناديق، وغيّر كلمات مرورها، واقرأ سجلّات DNS الدقيقة (SPF وDKIM وMX…) التي يحتاجها البريد — بنقرة لنشرها إن كانت المنطقة على هذا السيرفر. وتُعرض بيانات الاتصال لأي برنامج بريد، والبريد عبر الويب إن كان مُعدًّا.

الزيارات

زوّار الموقع وطلباته عبر الزمن (ساعة، يوم، أسبوع…)، مع تفصيل حسب المضيف. ولكل حساب عرض زيارات أوسع أيضًا.

الطرفية

طرفية ويب تعمل بهوية مستخدم الحساب نفسه، داخل جلسة معزولة — مفيدة لـ composer أو git أو أوامر سريعة دون دخول SSH كامل. ولا يمكنها الوصول إلى حساب آخر أو إلى النظام أبدًا.

النطاق الفرعي كموقع مستقل

كل نطاق فرعي موقع مصغّر قائم بذاته. يظهر في القائمة الجانبية تحت موقعه الأب، وبفتحه (أو زرّ نظرة عامة) تحصل له على صفحاته الخاصة:

  • نظرة عامة — نوعه وSSL وDNS ومجلده ومشاكله وإزالته.
  • الملفات — ينقلك إلى مجلده الخاص في مدير الملفات.
  • PHP أو Node — إصدار PHP الخاص به، أو تطبيق Node الخاص به، مستقل عن الموقع الأب.

ويبقى كل ذلك داخل مستخدم الحساب الأب وشريحته، فلا يكسر عزل الحساب أبدًا.

النسخ الاحتياطية للجميع

خذ نسخة احتياطية من حساب، وأرسلها خارج السيرفر كي لا يكون السيرفر المفقود نسخة مفقودة. أضف وجهة — MEGA أو أي تخزين متوافق مع S3 (Backblaze B2، Wasabi، Cloudflare R2) — اختبرها، ثم أنشئ النسخ واسترجِع منها بنقرة.

تحديث اللوحة مدير

تتحقّق اللوحة من قناة رسمية بحثًا عن إصدارات جديدة. وعند توفّر واحد يظهر شريط يعرض التحديث. ويُتحقَّق من التحديث مرّتين — بصمته وتوقيعه التعمية — ويُرفض إن فشل أيّهما، فلا يُثبَّت إلا بناءٌ أصيل من الناشر الحقيقي. ثم تُثبّته اللوحة وتعيد تشغيل نفسها؛ وتبقى مواقعك تعمل.

كيف تُحفظ بياناتك بأمان

  • فصل الصلاحيات — مساعد مميّز صغير يقوم بالعمل الفعلي؛ وواجهة الويب بلا صلاحيات خاصة بها، تطلب العمليات بالاسم فقط.
  • عزل لكل حساب — مستخدم لينكس وشريحة لكل حساب، بحدود المعالج والذاكرة والعمليات والقرص، يفرضها SELinux. والمهاجم داخل موقع لا يصل إلى آخر.
  • تحديثات موثّقة — كل تحديث يُفحص ببصمته وتوقيعه قبل تثبيته.
  • سجلّات محلية — تُسجَّل عمليات الدخول والأوامر على السيرفر نفسه؛ لا تتدخّل أي خدمة خارجية.
سؤال أو مشكلة؟ افتح مركز الحماية أولًا — فهو يشرح ويُصلح معظم الأمور وحده.
